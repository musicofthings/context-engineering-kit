The Problem

Agent sessions have a memory problem.

Compaction, device switches, usage resets mid-subagent, or runtime hop (Claude → Grok → Codex) can drop task state — unless you externalise it.

🔄

Context window fills up

Claude compacts the conversation and loses all the decisions, file paths, and task context you built up.

→ PreCompact hook saves everything before it's gone

💻

Switching devices

You're mid-task on your work machine. You open your laptop at home and have no idea where you left off.

→ session_sync.sh commits state to git — pull and resume anywhere

📊

No usage visibility

You hit the Pro limit with no warning and lose a long session. Or you switch to Opus for a trivial rename.

→ usage-sentinel prefers real rate-limit % and WRITES handover at 85%/92%

🆕

Every new repo starts cold

You clone a new repo and Claude has no awareness of what you were doing, the project structure, or conventions.

→ auto_activate_new_repos bootstraps context on first open

🔀

Subscription changes break flow

Pro → Max → API billing — each switch is a new session with no continuity.

→ Same git repo, same session_handover.md, same state across all tiers

🧹

Context rot

Default /compact summarises everything uniformly. Important code decisions get compressed the same as exploration noise.

→ /compact-smart preserves code and decisions at higher fidelity

🌲

Git worktrees fragment state

You spin up a worktree for a feature branch. Its state lives on a throwaway branch and vanishes when the worktree is removed — or worse, parallel sessions clobber each other's state.

→ One resolver + state.scope + lock-guarded writes keep state coherent

🔑

Can't find the session to resume

You want to claude --resume the exact conversation but don't know the session ID — and transcript resume silently breaks when the cwd changed.

→ Captures the SDK session ID; handover prints the exact resume command + cwd caveat

🖱️

Cursor has no context kit

You switched from Claude Code to Cursor and lost auto-save, compaction snapshots, and the dangerous-command guard — different hook system, no shared state.

→ .cursor/hooks.json adapters exec the same kit scripts; one state.json, two runtimes

How It Works

Hooks wire in automatically.

You install once. After that, every session start, compaction, and stop event is handled silently — in Claude Code or Cursor.

🚀

Session Start

State injected. New repos bootstrapped. Morning brief generated.

💬

Every Prompt

Usage tracked. Warnings injected at 70/80/85/92%. Auto-save triggers.

📦

Pre-Compact

Handover generated. State merged. Files committed to git.

♻️

Post-Compact

Task context re-injected. Claude picks up exactly where it left off.

🔚

Session End

All state files committed. Ready to resume on any device.

Features

Everything context preservation needs.

15+ hooks, 8 skills, and a suite of scripts — all working together silently, now worktree-aware, concurrency-safe, and available in Cursor.

Platform · v2.7 · Multi-runtime

.cursor/hooks.json

Cursor IDE project hooks: 10 events (sessionStart, beforeSubmitPrompt, beforeShellExecution, afterFileEdit, stop, …) routed through thin adapters in .cursor/hooks/ that exec the same .claude/hooks/*.sh logic. No plugin upload — open the repo in Cursor.

Core · v2.7

resolve_state_dir.sh

Single source of truth for where session state lives. Config-driven state.scope (auto / main / local) handles branch vs. git-worktree flows, with a portable lock-guarded state_write() so parallel sessions field-merge instead of clobbering.

Skill · v2.7 · Agent SDK

Session resume

SessionStart and Stop capture the SDK session_id and transcript path. /handover prints the exact claude --resume <id> command and warns when transcript resume is cwd-bound (e.g. started in a worktree).

Hook · PreToolUse

guard-dangerous.sh

Blocks destructive shell before it runs: rm -rf /, rm -rf ., quoted $HOME, separate -r -f flags, fork bombs, disk wipers, and writes to production.*. Defense-in-depth alongside canonical deny rules.

Hook · PermissionRequest

auto-approve-permissions.sh

Silently approves writes to context files and kit scripts (metachar-rejecting, anchored), so /handover and the hooks never interrupt you for permission — while .env and production paths stay denied.

Hook · PreCompact

pre-compact.sh

Saves session_handover.md, merges state.json (preserves all fields), updates CLAUDE.md, and commits to git before every compaction. Nothing is lost.

Hook · UserPromptSubmit

usage-sentinel.sh

Tracks Pro/Max/API usage against your 5-hour window. Injects warnings at 70%, save reminders at 80%, and auto-save directives at 85% and 92%.

Hook · SessionStart

auto_init_project.sh

Detects new git repos with no context-kit files and bootstraps them automatically. Controlled by auto_activate_new_repos in plugin_settings.json.

Skill

/compact-smart

Relevance-scored compaction. Tags code, decisions, and error solutions for verbatim preservation. Tags exploratory noise for aggressive summarisation.

Skill

/session-sync

Commits session_handover.md and state.json to git and pushes. On any new device: git pull → session_sync load → resume. Works across Pro ↔ Max ↔ API.

Skill

/token-status

Live view of your 5-hour window usage, context percentage, cost today, turns taken, and ETA to limit. Reads real rate_limits data from the Stop event.

Skill

/handover

Generates a structured session_handover.md with active task, completed items, remaining work, environment snapshot, and key decisions.

Skill

/model-switch

Switch between Haiku (fast/cheap), Sonnet (default), and Opus (complex reasoning). /model-switch auto analyses your task and recommends the right model.

Hook · PostToolUseFailure

post-tool-failure.sh

Logs every tool failure with tool name, error, and file path to tool-failures.jsonl and state.json. Failures surface in handover and context-health.

Hook · SubagentStart/Stop

subagent-lifecycle.sh

Tracks every spawned subagent: type, description, start/stop timing. Running count maintained in state.json for handover visibility.

Config

plugin_settings.json

Global feature toggles: enable/disable auto-activation, usage sentinel, morning brief, tool failure logging, and subagent tracking. Skip specific repos.

Platform

Windows-native

find_python.sh auto-detects python3 → python → py.exe (Windows Launcher) and verifies it's Python 3 before use. Works on every Windows setup.

For Cowork users (any role). The skills layer (slash commands) installs cleanly; shell hooks are no-ops in Cowork because there's no shell environment.

1

Download the plugin zip

Grab the prebuilt zip from GitHub Releases — no clone, no build needed.

context-engineering-kit-2.7.0.zip   # ~251 KB
2

Upload to Claude Cowork

Open Cowork → Settings → Plugins (or Skills → Add plugin) → Upload plugin → select the zip.

3

Use a skill

Type any of the eight skills as a slash command in a Cowork conversation:

Want the full hook layer (auto-save before compaction, git sync, usage sentinel)? Switch to the Code Desktop or Code CLI tab — Cowork doesn't run shell hooks.

Recommended for Claude Code Desktop users. Installs once, activates automatically in every project — skills and all 15 hooks.

1

git clone https://github.com/musicofthings/context-engineering-kit.git

Verify

For Cursor IDE users. Project hooks in .cursor/hooks.json route through adapters to the same kit scripts — no plugin upload, no separate codebase.

1

Clone the repo

Open your project folder in Cursor, or clone the kit into an existing project:

git clone https://github.com/musicofthings/context-engineering-kit.git my-project
cd my-project
2

Make hook scripts executable

chmod +x .cursor/hooks/*.sh .claude/hooks/*.sh scripts/*.sh

Requires bash, jq, and python3 on PATH — same as the CLI install.

3

Open in Cursor

Cursor loads .cursor/hooks.json automatically as project hooks. It watches the file and reloads on save — restart Cursor if hooks don't appear in Settings → Hooks.

4

Verify

Start an Agent session and check the Hooks output channel. Edit a file — state.json's changed_files should update. See the Cursor integration section for the full event map.

For Grok Build. Project hooks under .grok/hooks/ dispatch into the same .claude/hooks core. Trust the folder once so hooks run.

1

Clone / open the project

git clone https://github.com/musicofthings/context-engineering-kit.git my-project
cd my-project
2

Trust hooks

In Grok: open the project, then run /hooks-trust. Confirm the Hooks tab lists cek-hooks.json.

Cursor Integration

Same kit. Different runtime.

Cursor uses its own hook event model. The kit ships thin adapters that translate Cursor's payloads and exec the same .claude/hooks/*.sh scripts — one logic core, shared state.json.

Cursor event Adapter Kit script What it does
sessionStart on-session-start.sh session-start.sh Init state, clear sentinels, record session metadata
sessionEnd on-session-end.sh session-end.sh Git-commit session state on close
beforeSubmitPrompt on-prompt.sh usage-sentinel.sh Log usage %, arm threshold sentinels
beforeShellExecution guard-shell.sh guard-dangerous.sh Block destructive shell — exit 2 = deny
afterFileEdit track-edit.sh track-changes.sh Append edited paths to changed_files
stop on-stop.sh extract → tracker → stop Heuristic state extract + usage log + heartbeat
postToolUseFailure on-tool-failure.sh post-tool-failure.sh Log failures to tool-failures.jsonl
subagentStart/Stop on-subagent.sh subagent-lifecycle.sh Track delegated subagent work
preCompact on-precompact.sh pre-compact.sh Handover + CLAUDE.md + git snapshot before compaction

Claude Code vs Cursor — what's shared, what's different

✅ Shared (both runtimes)
  • state.json via resolve_state_dir.sh
  • session_handover.md + git snapshot commits
  • Dangerous-command guard
  • File-change tracking
  • Subagent lifecycle logging
  • Usage sentinel logging
⚠️ Claude Code only
  • PostCompact context re-injection
  • PermissionRequest auto-approve
  • Skill slash commands (/handover, etc.)
  • Desktop notification hook
